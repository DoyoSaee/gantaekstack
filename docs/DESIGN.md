# 간택스택 (GanTaekStack) — 설계 문서

> **시장이 간택하는 스택.** 채용공고를 수집·분석해 "지금 시장이 뭘 요구하는지"를 보여주고,
> 내 스택과 대조해 격차를 알려주는 서비스.

- **대회:** 원티드 AI Championship 2026 (접수 ~9/18 · 제출 ~9/20 · 본선발표 10/7 · 데모데이 10/17)
- **작성일:** 2026-09-15
- **형태:** 1인 · Next.js 풀스택 · 무료 데이터/모델 기반

---

## 1. 문제
- 개발자·구직자는 **"지금 시장이 어떤 기술을 요구하는지"**를 체계적으로 알기 어렵다.
- 채용공고는 흩어져 있고, `"React 3년"` 같은 표면 키워드 뒤에 **`"SSR 경험, 대규모 트래픽 환경"`** 같은 진짜 요구가 문장 속에 숨어 있다.
- 내 스택이 시장 대비 **어디가 비어 있는지** 객관적 지표가 없다.

## 2. 타겟
- **1차:** 구직·이직 중인 개발자 (**제작자 본인이 곧 1호 실사용자** — 내 실제 구직에 직접 씀)
- **2차:** 커리어 방향 잡는 주니어, 학습 우선순위 정하려는 사람

## 3. 핵심 가치 / 차별점
1. **집계지, 판정이 아니다** — "뜨는 기술"은 공고를 세어 나온 *사실*. AI가 지어내지 않는다.
2. **표면 키워드가 아니라 '숨은 요구'** — 공고 본문에서 실제 요구 역량을 LLM으로 구조화.
   → 이것이 "통계 사이트"와의 차별점이자 **프로젝트의 심장** (`lib/extract.ts`).
3. **시장 관찰 + 개인 격차** — 보는 데서 끝나지 않고 "그래서 나는?"까지 답한다.

## 4. 기능 (C 구조: A + B)

### A. 시장 관찰 (랜딩, 로그인 X)
- 이번 기간 **뜨는 기술 TOP N**
- **함께 등장하는 기술** (co-occurrence) — "이 기술과 항상 같이 요구되는 것"
- (데이터 쌓이면) **시간축 추이**
- 직무/지역 필터

### B. 개인 격차 (스택 입력 → 확장)
- 내 스택 입력 → **지원 가능 공고 비율** ("전체의 12%")
- 가장 임팩트 큰 격차 기술 (**"이거 하나 더하면 34%"**)
- 내 스택과 자주 함께 요구되는 기술 추천

> **흐름:** 랜딩은 A(진입장벽 0) → 스택 입력 시 B로 확장. 로그인 불필요.

## 5. AI 활용 방식 (심사 핵심축)
- **입력:** 공고 원문(제목 + 본문)
- **LLM 작업:** 구조화 추출 → `{ skills[], experienceYears, hiddenRequirements[] }`
  - 표면 스택뿐 아니라 문장 속 **암묵 요구**("SSR", "대규모 트래픽", "직접 배포 경험") 추출
  - 스킬 **정규화** (React = 리액트 = React.js → `"React"`)
- **모델:** Gemini (무료 티어, 대량 처리) · 품질 필요 시 Claude 스왑 가능
- **집계는 코드** (빈도·co-occurrence·추이) — AI는 "구조화"에만, 통계는 결정론.
- ⇒ **AI 역할 = "비정형 공고문 → 정형 데이터" 변환.** 판정·점수 없음.

## 6. 데이터 소스
| 소스 | 접근 | 역할 |
|---|---|---|
| **워크넷 채용정보 공공 API** (data.go.kr) | 개인 무료·즉시·합법 | **base** |
| **사람인 API** (oapi.saramin.co.kr) | 신청·승인 | **IT 커버리지 보강** |
| 원티드/잡코리아 | 개인 불가(B2B) / 크롤 금지 | ❌ 사용 안 함 |

- 어댑터로 **공통 스키마 정규화** → 소스 무관하게 파이프라인 동작(뭐가 먼저 오든 시작).

## 7. 아키텍처
```
[cron] → /api/collect → sources/{worknet,saramin} 어댑터 → 정규화 → DB(JobPosting)
                                   ↓
                         lib/extract.ts (Gemini)  → skills[] + hiddenRequirements[]
                                   ↓ 정규화
                         DB(Skill, PostingSkill)
                                   ↓
                         lib/aggregate.ts (빈도·co-occurrence·추이)
                                   ↓
        /api/stats ─→ A화면(시장 대시보드)   /api/gap ─→ B화면(개인 격차)
```
- **Next.js 16 (App Router)** 풀스택 · **Postgres**(Supabase 또는 홈랩) + **Prisma**
- **UI:** shadcn/ui + Recharts (shadcn `chart`)
- **배포:** Vercel (라이브 링크 · cron 내장 → "심사기간 접속 유지" 요건 안전)

## 8. 데이터 모델 (Prisma 개요)
- **JobPosting** — 원본: `source, sourceId, title, company, url, location, postedAt, collectedAt, rawText, extracted(JSON)`
- **Skill** — 정규화 스킬명 `name(unique), category`
- **PostingSkill** — 조인: `postingId ↔ skillId`
- → 빈도 / 공동출현 / 추이 / 격차 전부 이 3개로 계산.

## 9. 리스크 & 대응
| 리스크 | 대응 |
|---|---|
| "통계 사이트"로 밋밋 | **AI '숨은 요구' 추출 깊이**에 집중 (`extract.ts`가 심장) |
| 시간축 데이터 부족(마감까지 며칠) | 공고 **등록일 분포**로 초기 추이 + **현재 스냅샷 인사이트** 중심 데모 |
| 데이터 품질(워크넷 IT 얇음) | 사람인 승인 오면 보강, 없으면 워크넷 IT 필터로 MVP |
| 링크 접속 유지(심사 요건) | **Vercel 배포**로 안정 |
| 5일 크런치 | P0(A화면까지) 먼저 완결, B는 P1 |

## 10. 스코프 & 일정
- **P0 (반드시):** 수집 → AI 추출 → 집계 → **A화면** → **배포**
- **P1 (되면):** B화면(개인 격차) · 한국↔글로벌 비교 뷰
- **P2 (여유 시):** GitHub 주간 트렌드 섹션 — 같은 파이프라인(cron+DB+델타) 재활용, GitHub Search API(무료·토큰). "채용 + GitHub = 개발자 트렌드 레이더"
- **제출물:** 스크린샷 · 데모 시나리오 · 제출 폼
- **마감:** 접수 9/18 · 제출 9/20
